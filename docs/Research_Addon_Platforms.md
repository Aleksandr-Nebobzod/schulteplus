# Исследование: как устроены платформы, принимающие адд-оны (обзор для «Шульте Плюс»)

> Дата: 2026-08-16. Тип: исследование (не решение). Цель: найти мировые прецеденты платформ с
> пользовательскими дополнениями, чтобы спроектировать механизм простых упражнений на внимание
> (пример — задача Струпа: выбор слова/цвета в таблице) поверх трёх платформенных типов ШП.
> Связанные документы: `docs/ARCHITECTURE.md` (vision «упражнение = дескриптор + опц. код»),
> `docs/MODULAR_TRANSITION.md` (этапы перехода).

## 1. Резюме

1. Мир решает задачу «пользовательский контент с логикой» спектром из **5 моделей**: контент-данные → визуальные блоки → собственный язык (DSL) → встраиваемый скрипт в песочнице → полный код. Порог входа и выразительность растут вместе; сильные платформы строят **лестницу** между уровнями, а не выбирают один (Minecraft: ваниль → datapack → мод; GameMaker: DnD → GML).
2. В предметной области ШП (когнитивные задачи: Струп, Flanker, n-back) доминирует модель **«упражнение = данные + готовые типы шагов»**: jsPsych (JS, MIT), PsychoPy (Python, GPL), PEBL (свой язык, GPL). Задача Струпа выражается данными без кода (`{word, color, corrAns}`).
3. Прямых прецедентов «массовое сообщество создаёт когнитивные упражнения для мобильного приложения» не найдено. Ближайшие аналоги: **H5P** (веб: тип = код, контент = JSON), **Anki/AnkiDroid** (мобильный: шаблон карточки = HTML/CSS/JS в WebView), **Duolingo Incubator** (закрытая модель «фиксированные типы + контент авторов», программа закрыта в 2022).
4. **Свой мини-язык (в т.ч. BASIC-подобный) — самый дорогой путь.** Прецеденты E-Basic (E-Prime), PEBL, DMDX — многолетние коммерческие/академические проекты; учебный полный интерпретатор — ~2 000 строк Java (Crafting Interpreters). Домен фактически мигрировал на JS/Python (jsPsych, PsychoPy; Ren'Py построен «DSL поверх Python»).
5. Для Android исполнение пользовательского кода: **WebView** (рендер + JS, sandboxed renderer-процесс с API 26 — совпадает с minSdk проекта; есть ограничения) или **встраиваемые движки** (QuickJS ~190 КБ, LuaJ, Rhino — медленный). Ни один движок не является песочницей сам по себе — нужна модель ограничений: «код без доступа + мост» (Figma) или «VM с вырезанными библиотеками» (WoW, Roblox).

## 2. Таксономия подходов (5 моделей)

| # | Модель | Платформы-примеры | Что делает автор | Порог входа | Выразительность |
|---|---|---|---|---|---|
| 1 | **Контент/конфиг** (данные) | Super Mario Maker, Geometry Dash, Minecraft datapacks, H5P-контент, Kahoot, Quizlet, Duolingo (авторы курсов), Anki-колоды, WeakAuras | Заполняет данные в жёстком шаблоне/схеме | Очень низкий (дети) | Низкая: только вариации фиксированных механик |
| 2 | **Визуальная логика** (блоки/гаджеты) | Scratch, MakeCode, GameMaker DnD, LittleBigPlanet, Dreams, OpenSesame, E-Studio, PsychoPy Builder, SuperLab | Соединяет готовые блоки/компоненты | Низкий | Средняя; плохо масштабируется на сложных проектах |
| 3 | **Собственный язык (DSL)** | E-Prime (E-Basic), PEBL (.pbl), DMDX, Inquisit, GameMaker (GML), Ren'Py, Twine | Пишет скрипты на языке домена | Высокий | Высокая, но язык привязан к домену |
| 4 | **Встраиваемый скрипт в песочнице** | WoW-аддоны (Lua), Roblox (Luau), Tabletop Simulator (Lua), Balatro (Lua/SMODS), Anki-аддоны (Python), Anki JS-шаблоны, Figma-плагины (JS) | Пишет код на общем языке с ограниченным API | Средний (программисты-любители) | Высокая |
| 5 | **Полный код** | Minecraft Java-моды, Obsidian-плагины, браузерные расширения, Moodle qtype (PHP), H5P-типы контента (JS) | Пишет код с полным доступом | Высокий | Максимальная |

Закономерность: чем левее, тем безопаснее и дешевле для платформы; чем правее — тем больше возможностей и выше нагрузка на модерацию/поддержку.

## 3. Когнитивные конструкторы (самая близкая предметная область)

Платформы, где «упражнение» — это и есть объект описания. Исторически сложились **три модели описания упражнения**: императивный скрипт, декларативный конфиг, визуальный конструктор.

| Платформа | Модель | Пример описания триала | Лицензия / цена | Плюсы | Минусы |
|---|---|---|---|---|---|
| **E-Prime** | Визуальный конструктор E-Studio + **E-Basic** (диалект BASIC) в InLine-объектах | `Dim nCount As Integer`; `c.SetAttrib "Stim", Random(1,499)`; тайминг `c.Clock.Read` | Проприетарная, ~$995 perpetual | Эталон тайминга и интеграции с железом (EEG/fMRI); готовые парадигмы (Stroop) | Windows-only, дорого; скриптовая часть повышает порог |
| **PEBL** | Собственный язык `.pbl` (C-подобный), интерпретатор на C++ | `define Start(lPar) {...}`; `EasyLabel()`, `WaitForAnyKeyPress()`, `GetTime()`; Stroop в батарее (`color-stroop.pbl`, 1106 строк) | **GPL-2.0**, бесплатно | Открыт; 100+ валидированных тестов; с 2026 — веб-запуск (WASM) | Свой язык надо учить; нет визуального конструктора; маленькое сообщество |
| **Inquisit** | Собственный язык в XML-стиле: `<trial>`, `<block>`, `<expt>` | `<trial topicftpractice> /stimulustimes = [0=fixation; 700=target] /correctresponse = ("a")` | Проприетарная (Web от $395/2 мес) | Готовая библиотека скриптов с «Editable Parameters» (онбординг = скачай и поменяй); офлайн-сбор на мобильном | Дорого; язык в XML-стиле; данные привязаны к серверу Millisecond |
| **OpenSesame** | Визуальный конструктор + **Python** (inline_script) | `c = Canvas(); c.fixdot(); c.show()` | **GPL-3.0** | Самый низкий порог (обзоры: №1 «для непрограммистов»); бесплатен | Python-код не работает онлайн (OSWeb требует JS); точность тайминга чуть ниже |
| **PsychoPy + Pavlovia** | Builder (GUI) + Coder (**Python**); онлайн — трансляция в PsychoJS | Builder-Stroop: conditions-CSV (`thisWord`, `thisColor`, `corrAns`) + loop | **GPL-3.0** (copyleft) | Builder для новичков, Python для всех остальных; крупнейшее сообщество; тайминг <1 мс | GPL при копировании кода; онлайн-стек ограничивает Python |
| **jsPsych** | **JS**: эксперимент = timeline — массив объектов-триалов (плагин + параметры); вариации через `timeline_variables` | `var trial = {type: 'html-keyboard-response', stimulus: 'hello world!'}`; для Струпа — строки `{word, color, corrAns}` | **MIT** — можно в коммерческом закрытом коде | Модульность «эксперимент = данные + типы триалов» — концептуально самый близкий прецедент; готовые шаблоны (flanker, n-back) | Нужен JavaScript; тайминг RT зависит от устройства (заявлено +10–40 мс к E-Prime) |
| **DMDX** | Собственный мини-язык в RTF-файле (`<ep>`-заголовок + item-строки) | `+1 *<ms% 500>"TARGET";` | Freeware (запрещена продажа) | Бесплатен; миллисекундная точность (Windows/DirectX); текстовый формат генерируется скриптами | Windows-only; плотная нотация; разработка заморожена |
| **SuperLab** | Point-and-click редактор без языка (rules, trial variables) | — (GUI) | Проприетарная | Самый «непрограммистский» подход; суб-мс точность | Язык исчез из новых версий — меньше гибкости; Mac-центричный |

**Вывод раздела:** доминирующая тенденция — декларативный конфиг: «упражнение — это данные, а не код» (jsPsych timeline, conditions-CSV PsychoPy, item-строки DMDX). Задача Струпа и родственные (Flanker, n-back, «найди лишнее») полностью выразимы конфигом без единой строки кода.

## 4. Образовательные платформы «шаблон + контент»

| Платформа | Модель | Автор | Плюсы | Минусы | Лицензия |
|---|---|---|---|---|---|
| **H5P** | Тип контента = код (JS + `semantics.json` — схема параметров); контент = чистый JSON, заполняемый в форме, генерируемой из схемы. Пакет `.h5p` (ZIP). | Новичок: формы в браузере. Разработчик: новый тип — код | Самый явный образец разделения схема/данные; **мини-игры по конфигу**: Memory Game, Drag and Drop (пары, dropzone-связи, значения — всё конфиг); ~50+ готовых типов; xAPI | Новый тип — только руками разработчика; схема зашита в БД при установке; веб-ориентирован (для нативного — нужен WebView-рантайм) | Ядро MIT; часть типов GPL |
| **Kahoot / Quizizz** | Закрытый набор фиксированных типов вопросов (5–20); контент в закрытой платформе | Создаёт квиз из типов; копирование чужих | Нулевой порог; огромные библиотеки UGC; режимы игры из одного контента | Контент заперт в платформе (нет экспорта/стандарта); расширение типов невозможно; модерация реактивная (карантин 24 ч) | Проприетарные |
| **Quizlet** | Один фиксированный шаблон «термин–определение»; из одного набора — 6+ режимов изучения | Создаёт наборы, импорт из документов | Минимальная модель контента; один формат обслуживает много логик | Один единственный шаблон | Проприетарная |
| **Duolingo (Incubator)** | Фиксированные типы задач (перевод, tap-the-pairs, диктант…); авторы курсов наполняют контент в закрытом редакторе; нотация вариантов `"[He/She] went to the park"` | Волонтёры-билингвы (курс = дерево уроков), QA фазами | Один контент обслуживает много типов задач; жёсткая схема → предсказуемое качество | Всё закрыто (схемы, редактор, API); программа закрыта в 2022 — перешли на наёмных авторов | Проприетарная |
| **Anki / AnkiDroid** | **Тип заметки = поля (контент) + HTML/CSS/JS-шаблон**. Мини-логика живёт в контенте (MCQ, drag-and-drop шаблоны) | Создаёт типы заметок и колоды без правки кода приложения | Сильнейший прецедент «контент с мини-логикой» на **Android** (WebView); открытый формат `.apkg`; огромное сообщество | JS в контенте = риск XSS и хрупкость (ломается при обновлениях); на AnkiDroid: **нет JS-состояния между фронтом/бэком карточки, общий scope сессии** (issue #14326); FAQ советует избегать JS | AGPL-3.0 (десктоп и Android) |
| **Khan Academy (Perseus)** | Упражнение = данные «perseus format» (itemData: виджеты + options + версии); рендерер отображает и проверяет | Сообщество — только перевод; контент пишут сотрудники | **Явное версионирование формата** (глобальная версия + per-widget) — образец эволюции без поломки старого | Не предназначен для внешнего использования (community-форк OpenPerseus) | Perseus MIT |
| **Moodle (qtype)** | Тип вопроса = PHP-плагин (5–7 классов: логика, рендер, формы, backup/restore); контент — записи БД через формы | Учитель: вопросы форм. Разработчик: новый тип — PHP | Открытый многолетний образец экосистемы плагинов; переносимый формат (XML) | Высокий порог для нового типа; GPL-виральность ограничивает коммерческие плагины | GPLv3+ |
| **SuperMemo** | Контент «вопрос–ответ» + универсальный алгоритм повторения (SM-2…SM-17) | Любой контент, нет типов взаимодействия | Контент не ограничен типами; алгоритм отделён от контента | Интерактивных типов задач нет | Проприетарная (алгоритмы опубликованы) |

**Модерация UGC** (везде ретроспективная): жалобы + автоматический скрининг + специальные контуры (Kahoot: флаг → карантин ~24 ч; Quizlet: приоритетные жалобы учителей, DMCA; AnkiWeb: задержка публикации на сутки под проверку копирайта; Scratch: статусы Unreviewed/For Everyone/NFE + автораскрытие при массовых жалобах).

## 5. Игровые UGC-платформы

| Платформа | Модель | Безопасность | Плюсы | Минусы |
|---|---|---|---|---|
| **Roblox** | Luau (диалект Lua) + контент; исполнение на клиенте **и на сервере** (сервер — источник истины) | 3 уровня: язык безопасен для встраивания (вырезаны `io`/`package`/`os.execute`, глобалы readonly, `loadstring` без байткода); **Script Capabilities** (группы возможностей UGC-скриптов); модерация ML + людьми | Полная вертикаль «создал → опубликовал → монетизировал»; защита от читов сервером | Экономика забирает 30–40%; зависимость от политики платформы; Luau — не стандартный Lua |
| **WoW-аддоны** | Lua + XML, строго UI-only; API жёстко ограничен | **Taint-система**: код аддона «пачкает» данные; защищённые функции (действия в бою) отказывают из «грязного» контекста; нет ФС/сети; обфускация запрещена | Ограниченный API почти исключает вред; бесплатно и открыто | Монетизация запрещена (политика); API намеренно неудобен; нет сетевых запросов |
| **GameMaker** | **GML (свой язык)** + визуальный DnD, где каждый блок = GML под капотом (Code Preview) | Движок не исполняет чужой контент — угрозы вне модели | Плавное эшелонирование DnD → GML; низкий порог для 2D | Нет UGC-платформы (обмена/монетизации сообщества); GML нигде больше не применим |
| **PICO-8 / TIC-80** | Картридж на Lua с жёсткими лимитами (128×128, 16 цветов, 8192 токена) | Офлайн-инструмент; чужой код — только по явному выбору | Лимиты как фича: мгновенный цикл, минимализм; картридж = PNG-файл | Lua обязателен; нет встроенного UGC-обмена |
| **Minecraft** | **Два уровня**: datapacks (JSON + `.mcfunction`, контент без кода, работает у всех) и Java-моды (полный код, установка каждому) | datapacks — конфигурация внутри движка (безопасно); моды — произвольный код с доступом к ФС | Лестница «ваниль → datapack → мод»; datapacks переживают обновления | datapacks бессильны вне ванильных систем; моды ломаются между версиями |
| **Scratch / MakeCode** | Визуальные блоки; MakeCode — двусторонний конвертер **блоки ↔ TypeScript** | Scratch: 4-ступенчатая модерация для детей; MakeCode: чужой код не исполняется у пользователей | Нулевой порог; MakeCode — лучший пример эшелонирования «блоки ↔ текст» | Блочный предел выразительности; нет экономики авторов |
| **Super Mario Maker** | Только контент: расстановка объектов, механики фиксированы | Вредоносного контента нет по построению | Нулевой порог; «честное» поведение | Нельзя создать новое правило/жанр |
| **Twine / Ren'Py** | Свой формат/язык (Twine: пассажи + макросы + JS; Ren'Py: screenplay-подобный + Python) | Песочницы нет — исполняемый файл = произвольный код | Эшелонирование «текст → переменные → макросы → код»; экспорт HTML | Нет платформы: нет обмена/модерации/монетизации |
| **LBP / Dreams** | Визуальная логика без текстового кода (гаджеты/правила) | Кураторство вручную (отдел кураторов Dreams распущен в 2024) | Самый низкий порог для «логики» | **Урок: UGC умирает вместе с сервером платформы** (LBP-серверы закрыты с 2021–2024, Dreams — конец поддержки 2023); визуальные схемы плохо масштабируются |

**Прецеденты «мини-игра/конфиг как данные»** (прямо релевантны ШП):
- **Geometry Dash** — уровни целиком = данные (объекты, позиции, триггеры; base64+gzip), без скриптов; десятки миллионов уровней при нулевом коде.
- **WeakAuras (WoW)** — обмен UI-конфигурацией **одной текстовой строкой** (`!WA:2!...`), импорт/правка через GUI без Lua. Паттерн «шеринг конфига строкой».
- **Tabletop Simulator** — встроенный Lua (MoonSharp, Lua 5.2) с ограниченным набором стандартных библиотек («safe sandbox»): нет `debug`, нет ФС; но есть WebRequest — скрипты могут связываться с серверами автора (риск эксфильтрации; хост может отключить скрипты).
- **Balatro (SMODS)** — готовая игра + узкий, но настоящий скриптовый API: мод = `mod.json` + `main.lua`, контент регистрируется через API.

## 6. Техника исполнения на Android (факты для выбора)

### 6.1. Встраиваемые движки

| Движок | Язык | Размер / скорость | Безопасность при встраивании | Интеграция в Kotlin/Java | Лицензия | Примеры применения |
|---|---|---|---|---|---|---|
| **WebView (системный)** | JS (V8) + HTML/CSS | Рендер в отдельном **sandboxed renderer-процессе** с API 26 (совпадает с minSdk ШП) | Изоляция процесса; мост JS↔Kotlin через `addJavascriptInterface` (нужно версионировать) | Готовая инфраструктура | системный | **AnkiDroid** (шаблоны карточек), Telegram Mini Apps, FB Instant Games |
| **QuickJS** | ES2020+ | ~190 КБ–1 МБ; нет JIT | **Встроенные лимиты**: `JS_SetMemoryLimit`, `JS_SetInterruptHandler` (CPU), `JS_SetMaxStackSize`; но это не песочница (Zipline: «run only trusted code») | JNI-обвязки: `taoweiji/quickjs-android`, `app.cash.quickjs` (Zipline) | MIT | Cash App Zipline (обновление бизнес-логики на Android API 18+) |
| **Hermes** | ES2019+ | AOT-байткод, нет JIT | Как все C-движки: в процессе, без изоляции | Сложно standalone: официальный AAR без `libjsi.so` — сборка из исходников | MIT | React Native на Android (по умолчанию с RN 0.70) |
| **Rhino** | ES6 | jar ~1,3 МБ; **медленный на Android** (интерпретаторный режим, нет генерации class-файлов) | Счётчик инструкций против бесконечных циклов; нет лимитов памяти | Простейшая (чистый Java), нужны ProGuard-правила | MPL-2.0* | Auto.js (автоматизация) |
| **LuaJ** | Lua 5.2 | компактный; быстрее Rhino | Песочница строится **вырезанием библиотек** (`io`/`os`) из окружения | Простая (JSR-223/прямой API); есть пример под Android в репозитории | MIT* | CC:Tweaked (Minecraft), OpenComputers — оба патчили LuaJ ради безопасности |
| **GraalJS** | JS | — | — | **Не работает на Android** (нет `sun.misc.Unsafe` в ART, issue #514) | — | только десктоп/сервер |

\* лицензии по репутации проектов, двумя источниками не подтверждены (кроме QuickJS и Hermes — MIT подтверждены).

### 6.2. Модели песочниц (как платформы защищают пользовательский код)

| Модель | Изоляция | Примеры | Стоимость для платформы |
|---|---|---|---|
| **Ограниченный API + мост сообщений** | Код исполняется в контексте без доступа (нет DOM, сети, файлов); связь только через postMessage | **Figma** (плагины), Telegram Mini Apps, FB Instant Games | Средняя (дизайн API, мост, сериализация) |
| **VM с вырезанными библиотеками** | Исполнение в процессе; нет ФС/сети; лимиты ресурсов | **WoW** (taint), **Roblox** (Luau + capabilities), Tabletop Simulator | Низкая–средняя |
| **Доверие + ревью/скан** (без песочницы) | Полный доступ к приложению; защита — Restricted Mode, автоскан, ручное ревью, удалённое отключение | **Obsidian** (прямо признаёт отсутствие песочницы), VSCode | Низкая на платформу, высокая на модерацию |
| **Изоляция процесса ОС** | `android:isolatedProcess` — эфемерный UID, SELinux `isolated_app`, связь только через Binder | Chrome renderer | Высокая (нет ContentResolver, лимиты IPC) |

### 6.3. Свой мини-язык: оценка трудозатрат

- Учебный полный интерпретатор — «less than two thousand lines of Java» (jlox, Crafting Interpreters); байткод-VM — существенно больше. Это без редактора, отладчика, сообщений об ошибках, документации.
- Продуктовые DSL домена существуют и работают (PEBL — один автор, C++-интерпретатор; E-Basic — коммерческий продукт ~20 лет), но это «самостоятельный продукт в продукте».
- Показательный сдвиг домена: современные инструменты экспериментов уходят от собственных языков к обёрткам над общими (Ren'Py — поверх Python, PsychoPy — Python, jsPsych — JS).

### 6.4. Ограничения WebView (факты из AnkiDroid/Chrome)

- Таймеры в фоне троттлятся (минимум 1 с; интенсивный троттлинг Chrome 88+ — 1 мин; `requestAnimationFrame` в скрытой странице не работает). Для видимого на переднем плане WebView некритично.
- Фрагментация: приложение зависит от версии системного WebView (AnkiDroid «ломали» баги рендера Chrome 131).
- file:// и CORS: нужен специальный origin (`appassets.androidplatform.net` у AnkiDroid) для локальных ресурсов.
- Мост JS↔Kotlin не версионирован у AnkiDroid — шаблоны ломаются при изменениях (issue #6328). Урок: версионировать мост.
- Нет событий `window.onload`/`DOMContentLoaded`, глобалы не сохраняются между фронтом/бэком (issue #14326) — нужны свои конвенции инициализации.

## 7. Сводная таблица плюсов/минусов (по подходам для ШП)

| Подход | Плюсы | Минусы | Ориентир стоимости разработки в ШП | Вердикт для ШП |
|---|---|---|---|---|
| **1. Конфиг-данные (JSON)** — фиксированные типы шагов + контент-наборы авторов | Максимально безопасно (парсер, не интерпретатор); совместимо с обновлениями; простой обмен файлом/строкой (паттерн WeakAuras); Струп и родственные задачи **полностью выразимы**; ложится на существующий дескриптор vision | Ограничено заранее заданными типами; «новый тип упражнения» — всегда задача разработчика | Низкая: схема + валидация + рендер на нативных экранах + редактор наборов | **Базовый уровень (рекомендуется)** — аналог Minecraft datapacks |
| **2. Фиксированные типы + контент (закрытая платформа)** | Нулевой порог автора; предсказуемое качество; один контент → много режимов (Quizlet) | Контент заперт в платформе; нет экспорта; расширение типов невозможно | Средняя (редактор, библиотека, модерация) | Подходит как **политика каталога** поверх уровня 1 |
| **3. Визуальный конструктор (блоки)** | Самый низкий порог для «логики» (Scratch, OpenSesame); безопасно | Дорого в разработке (UI-движок блоков); на мобильном экране тесно; сложная логика нечитаема | Высокая | **Второй уровень, опционально** — блоки могут компилироваться в тот же JSON уровня 1 (MakeCode-паттерн) |
| **4. Встраиваемый JS/Lua в песочнице** | Мощно; известный синтаксис; готовые движки (QuickJS ~190 КБ, LuaJ) и прецеденты песочниц | Ни один движок не песочница сам по себе — нужны лимиты памяти/CPU + урезанный API + контроль моста; порог для авторов | Средняя–высокая (движок + модель ограничений + тестирование) | **Третий уровень, позже**, после стабилизации уровней 1–2; Lua дешевле своего языка (прецедент WoW/TTS/Balatro) |
| **5. Свой мини-язык (BASIC-подобный)** | Точно под домен; «обучает» сообщество; полный контроль | Самый дорогой путь: интерпретатор ~2000 строк только учебный; редактор+отладка+доки — продукт в продукте; прецеденты (E-Basic, PEBL, DMDX) — многолетние проекты; домен мигрирует на JS/Python | Очень высокая | **Не рекомендован** как стартовый вариант; рассматривать только при доказанном спросе и при готовности поддерживать язык годами |
| **6. WebView как рантайм исполнения** | Рендер + JS + изоляция из коробки (sandboxed renderer на API 26); весь DOM/Canvas для стимулов; jsPsych доказывает: Stroop-класс задач — часы разработки | Троттлинг таймеров в фоне; фрагментация системного WebView; CORS/file://-нюансы; точность тайминга RT ограничена (ориентир +10–40 мс к E-Prime); мост надо версионировать | Низкая (для уровня 4) | **Альтернатива движку для уровня 4** (образец — AnkiDroid); требуются замеры тайминга на целевых устройствах |

**Дополнительные факторы, общие для всех уровней:**
- **Модерация**: пока контент создаётся локально и шарится файлом/строкой — не нужна; при публичном каталоге — репорт-флоу + премодерация ~24 ч (паттерн Kahoot/AnkiWeb) или статусы ревью (Scratch).
- **Жизненный цикл**: UGC, живущий только на сервере платформы, умирает вместе с сервером (LBP/Dreams) → формат должен быть портабельным (файл/строка), а каталог — опциональным слоем.
- **Экономика**: два полюса — запрет продаж (Blizzard) и комиссия 30–40% (Roblox). Промежуточных моделей в найденных прецедентах нет — вопрос продукта, не техники.
- **Статистика**: для сопоставимой статистики (журнал `Turn` в vision ШП) любой формат должен писать результат в единую схему — это сильный аргумент за уровни 1–2, где событийная модель фиксирована.

## 8. Применимость к «Шульте Плюс» (факты и аналогии, без решения)

1. **Соответствие vision**: `docs/ARCHITECTURE.md` уже определяет «упражнение = дескриптор (JSON) + опциональный код (плагин)». Исследование подтверждает: модель «дескриптор = данные» — доминирующая в мире (jsPsych, H5P, Duolingo, Minecraft datapacks), а «опциональный код» во всех прецедентах — это JS/Lua в песочнице, а не свой язык.
2. **Задача Струпа** (пример пользователя: выбор слова/цвета в таблице) — канонический когнитивный тест, для которого в мире есть готовые описания: в jsPsych это данные `{word, color, corrAns}` + тип триала; в PEBL — готовый `color-stroop.pbl` из батареи; в Inquisit — готовые скрипты с «Editable Parameters». Все три подтверждают: конфиг покрывает задачу.
3. **Онбординг авторов** во всех когнитивных платформах строится на библиотеке готовых экспериментов с правкой параметров (Inquisit, PEBL), а не на языке с нуля — это дешевле конструктора и надёжнее для сообщества.
4. **Собственный язык** в мире ШП есть (E-Basic, PEBL, DMDX), но все они: закрытые или академические, многолетние, с малым сообществом. Ни один массовый потребительский продукт на этом не построен.
5. **Открытые вопросы, требующие отдельной проверки** (в этом исследовании не покрыты): политики Google Play / App Store в отношении загрузки и исполнения кода интерпретаторами; реальная точность тайминга WebView/QuickJS на Android-устройствах (нужны замеры на целевых устройствах); лицензии при заимствовании кода у jsPsych (MIT — можно) и OpenSesame/PsychoPy (GPL — только референс).

## 9. Достоверность и ограничения исследования

- Ключевые факты проверены по 2+ источникам (официальные доки, репозитории, обзоры); у агентов был недоступен WebFetch — часть цитат взята из сниппетов поисковой выдачи.
- Цены (E-Prime ~$995, Inquisit от $395/2 мес, GameMaker $99.99/год) — с официальных страниц продавцов, без скидок.
- **Не подтверждено / требует проверки**: политики магазинов по интерпретаторам; цена SuperLab в USD; текущая цена Pavlovia; точная JSON-схема уроков Duolingo (закрыта); событие «GameMaker runtime-fee 2025» (источники не нашли); лицензии Rhino/LuaJ (по репутации); «QuickJS-песочница в Figma» (сторонний анализ, не официальные доки).
- Маркетинговые цифры (0,5 млрд вопросов Kahoot, 20M+ активностей Quizizz, $1,1 млн доходов топ-разработчиков Roblox) — заявления платформ, независимо не проверены.
